★ The whole secret in one line
DMA copies bytes from USART to memory without the CPU. The CPU only wakes up when a complete frame is ready — once per ~890 ms instead of once per ~87 µs (10 000× fewer wake-ups).

During development we hit a real bug: the bootloader was losing the first data frame and the host had to NACK-retry. The diagnostic logs traced it to a timing race in the DMA re-arm sequence. Here is exactly what was happening — and why moving one line of code fixed it.

⚠ Root cause & fix
The original code sent ACK first, then re-armed DMA. The host received ACK in ~1–5 ms and started streaming the next 10 KB frame immediately — but DMA was still offline, so the USART overran within microseconds.

Fix: swap the order — call restart_dma_receive() before etx_send_response(ACK). DMA must always be ready before you authorize the peer to send.
